#260 - Client Sentiment & Review Automation

## What & Why

Add a customer review automation system for organizations using Hubify.

Home Watch companies should be able to track their clients’ satisfaction over time and automatically request public reviews when a client has had a positive experience.

The goal is not to ask every client for a review blindly. Hubify should first track private satisfaction/sentiment, then trigger a public review request only when the client gives a strong rating.

This helps organizations:
- measure client happiness
- catch unhappy clients before they leave
- request reviews at the right time
- generate testimonials for marketing/social media
- follow up automatically when a client does not complete the review

## Important Compliance / Platform Rule

Do not build this as “Hubify automatically posts a review to Google/Facebook on behalf of the client.”

Instead:
- Hubify can send the review request.
- Hubify can collect private satisfaction feedback.
- Hubify can collect a testimonial/review draft.
- Hubify can provide links/buttons to Google, Facebook, Yelp, etc.
- Hubify can prepare social media/testimonial copy for the organization.
- The client must personally submit public reviews to third-party platforms.

## Feature Name

Use this language in the UI:

- Client Sentiment
- Review Automation
- Review Requests
- Testimonials
- Satisfaction Score
- Follow-Up Reminder

Avoid language that implies fake, forced, or automatically posted third-party reviews.

# Core Flow

## Flow 1: Private Satisfaction Check

After a service season, completed project, completed inspection cycle, or manually selected milestone, Hubify sends the client a satisfaction check.

Example:

“How was your experience with [Organization Name] this season?”

Client selects:

- 5 stars / Very satisfied
- 4 stars / Satisfied
- 3 stars / Neutral
- 2 stars / Unsatisfied
- 1 star / Very unsatisfied

Optional fields:

- What went well?
- What could have been better?
- May we use your comments as a testimonial?

## Flow 2: Positive Rating Triggers Review Request

If rating is above threshold, default 4 or 5 stars:

Hubify automatically sends a public review request.

Example:

“Thank you for the kind feedback. Would you be willing to share your experience publicly?”

Buttons:
- Review us on Google
- Review us on Facebook
- Leave a testimonial
- Copy my feedback

## Flow 3: Low Rating Creates Internal Alert

If rating is below threshold, default 1–3 stars:

Do not request a public review.

Instead:
- create internal alert
- mark client as attention needed
- notify organization admin/supervisor
- optionally create follow-up task

Example internal message:

“Client gave a 2-star satisfaction score. Follow up recommended before requesting a review.”

## Flow 4: Automatic Circle-Back

If a client gives a high rating but does not complete the review request:

Hubify should automatically follow up.

Default follow-up cadence:

- initial review request immediately after positive satisfaction score
- reminder 3 days later
- reminder 7 days later
- final reminder 14 days later

Stop reminders if:
- client submits testimonial
- client clicks “I already reviewed”
- client opts out
- max reminder count reached

# Admin Settings

Add organization-level Review Automation settings.

Settings should include:

- enable/disable review automation
- satisfaction threshold for review request, default 4
- follow-up cadence in days, default [3, 7, 14]
- max reminders, default 3
- Google review URL
- Facebook review URL
- Yelp review URL optional
- custom review URL optional
- default email subject
- default SMS/message body if messaging exists
- allow testimonial collection yes/no
- require approval before using testimonial publicly yes/no
- auto-create follow-up task for low ratings yes/no
- staff/admin notification recipients

# Backend API

Add API routes under:

`/api/reviews`

All organization admin/supervisor routes should be authenticated and scoped to `req.user.orgId`.

## Admin Routes

### GET `/api/reviews/settings`
Get org review automation settings.

### PATCH `/api/reviews/settings`
Update org review automation settings.

### GET `/api/reviews/sentiment`
List client sentiment surveys with filters:
- status
- rating
- clientId
- propertyId
- date range

### POST `/api/reviews/sentiment/send`
Manually send satisfaction survey.

Request body:
- clientId
- propertyId optional
- triggerType
- customMessage optional

### GET `/api/reviews/requests`
List review requests.

### POST `/api/reviews/requests/:id/remind`
Manually send reminder.

### POST `/api/reviews/requests/:id/mark-reviewed`
Mark client as already reviewed.

### GET `/api/reviews/testimonials`
List testimonials.

### PATCH `/api/reviews/testimonials/:id`
Update approval status / marketing permission.

## Public Client Routes

Use secure tokenized links.

### GET `/r/satisfaction/:token`
Public satisfaction form.

### POST `/r/satisfaction/:token`
Submit rating and private feedback.

If rating >= threshold:
- create review request
- show public review options
- send review request follow-up email if needed

If rating < threshold:
- create internal alert/task
- do not show public review links aggressively

### GET `/r/review/:token`
Public review request page.

Shows:
- Google review button
- Facebook review button
- Yelp review button if configured
- testimonial form
- “I already reviewed”
- opt-out option

### POST `/r/review/:token/testimonial`
Submit testimonial.

### POST `/r/review/:token/already-reviewed`
Mark already reviewed.

### POST `/r/review/:token/opt-out`
Opt out from reminders.

# Automation / Scheduled Job

Add a scheduled job to send review reminders.

Suggested function:

`processReviewRequestReminders()`

Runs daily.

Logic:
- find review_requests where status is sent/pending/clicked
- nextReminderAt <= now
- reminderCount < maxReminders
- not opted out
- not already reviewed
- not testimonial submitted
- send reminder email/message
- increment reminderCount
- set nextReminderAt based on settings follow-up cadence
- expire when max reminders reached

---

# Trigger Points

Do not trigger everywhere at first.

Start with manual trigger plus one automatic trigger.

Phase 1 triggers:
- manual send from client/property profile
- season completed/manual milestone

Phase 2 triggers:
- after report sent
- after invoice paid
- after a recurring service period ends
- after final visit of a seasonal itinerary/service assignment

# Acceptance Criteria

- Organization admin can enable/disable review automation.
- Organization admin can configure review platform URLs.
- Admin/supervisor can manually send satisfaction survey to a client.
- Client can submit private satisfaction rating from a secure public link.
- Positive ratings create a review request.
- Low ratings create internal follow-up alert and do not trigger public review request.
- Review request page shows configured external review links.
- Client can submit a testimonial.
- Client can mark “I already reviewed.”
- Client can opt out of reminders.
- Reminder job follows up automatically when review is not completed.
- Reminder job stops when completed, opted out, already reviewed, or expired.
- Testimonials can be approved before marketing use.
- Dashboard shows sentiment/review metrics.
- All records are scoped by orgId.
- No third-party public review is auto-posted without client action.
